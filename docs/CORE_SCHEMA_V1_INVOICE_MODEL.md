# Core Schema V1: オーダー・請求書IDモデル

## 確定した関係

Core Schema V1では、請求書を次の順序で追跡する。

```text
リード管理
  └─ 顧客マスタ
       └─ オーダー管理
            ├─ オーダー明細
            └─ 請求書管理
                 └─ 請求書明細
```

- 顧客マスタは `源流リードID` でリード管理を参照する。
- オーダー管理は `顧客ID` と `源流リードID` を保持する。
- 請求書管理は `請求書ID` を主キーとし、`オーダーID` と `顧客ID` を参照する。
- 請求書明細は `明細ID` を主キーとし、`請求書ID` と `商品ID` を参照する。
- 1つのオーダーIDを複数の請求書行から参照できる。請求書が複数回に分かれても、請求書IDは発行ごとに別にする。
- 請求書管理に `商談ID` は持たせない。リードはオーダー・顧客の参照関係から追跡する。

## 今回の変更範囲

- `INVOICES` と `INVOICE_LINES` をCore Schema V1 Registryへ登録する。
- 既存Configの `INVOICES` / `INVOICE_ITEMS` をRegistry経由で解決する。
- 既存Configの請求書管理ヘッダー3列目を `商談ID` から `オーダーID` へ変更する。
- 既存Configに定義済みだったその他の請求書管理29列・請求書明細15列は維持する。

## 現行請求書発行経路で確認した制約

`transferAndGeneratePDF()` は現在、固定GIDで旧入力・旧出力シートを取得し、請求書番号を採番して旧「取引状況」相当へ明細を転記する。現在の処理には、次の書込みはない。

- オーダーIDの新規発行または既存オーダーIDの再利用
- 請求書IDの発行
- 請求書管理への書込み
- 請求書明細への書込み

このため、今回のRegistry登録だけでは請求書発行経路は切り替わらない。

新規スタッフ追加

重要： スタッフを追加した後、必ずGCP OAuth設定でテストユーザーに追加してください。 登録ガイドを見る

スタッフ登録ガイド

新しいスタッフがアプリを利用できるようにするには、以下の2つの作業が両方必要です。どちらか一方だけでは入れません。

1

スタッフマスタに登録する

アプリ内でスタッフ情報と権限を登録します。

登録手順
  1. 管理者メニュー → スタッフ を開く
  2. 「+ 新規スタッフ追加」ボタンをクリック
  3. 氏名・メールアドレス・ロールを入力して保存
重要： メールアドレスはGoogleアカウントと完全一致している必要があります。
2

Google Cloud ConsoleでOAuth認証ユーザーを追加する

このアプリはGoogle Cloud PlatformのOAuth認証を使用しています。現在「テスト中」モードのため、許可したユーザーのみアクセス可能です。

登録手順
  1. 下の「GCP コンソールを開く」ボタンをクリック
  2. 「テストユーザー」セクションを確認
  3. 「+ ADD USERS」をクリック
  4. 追加するスタッフのGoogleアカウントのメールアドレスを入力
  5. 「SAVE」をクリック
注意： テストユーザーの上限は100名です。上限に達した場合は「本番公開」への変更が必要です。

登録完了チェックリスト

☐ スタッフマスタにメールアドレスを登録した
☐ GCPコンソールのテストユーザーにメールアドレスを追加した
☐ スタッフ本人がアプリにアクセスして動作確認した

            CSVインポート使い方ガイド
          

        


        
        

          
        


        
        

          

            
            データ移行フロー
          


          

            
            

              

                
1

                
Phase 1: リード管理データ移行

                
親データ

              

              

                
既存顧客リスト.csv → LDI-00001, LDI-00002...

                
✓ リードIDを自動生成　✓ メールアドレスで重複チェック

              

            


            
↓


            
            

              

                
2

                
Phase 2: 顧客マスタデータ移行

                
親データ

              

              

                
成約済み顧客リスト.csv → CT-00001, CT-00002...

                
✓ 顧客IDを自動生成　✓ 請求先・配送先情報を登録

              

            


            
↓


            
            

              

                
3

                
Phase 3: 会話ログデータ移行

                
子データ（要リードID）

              

              

                
会話履歴.csv → LOG-00001 → LDI-00001

                
✓ ログIDを自動生成　✓ メール/電話/顧客名でリード検索・紐付け

              

            


            
            

              

                
                なぜこの順番なのか？
              

              

                

                  データ依存関係: 会話ログは「リードID」という外部キーを持つため、親データ（リード管理）が先に存在する必要があります。
                

                

                  

                    

                      
                      正しい順序
                    

                    
リード管理 → 会話ログ

                    
リードが存在するため紐付け成功

                  

                  

                    

                      
                      間違った順序
                    

                    
会話ログ → リード管理

                    
リードが未登録のためエラー100%

                  

                

              

            

          

        


        
        

          

            
            会話ログのリード自動紐付けロジック
          


          

            

              会話ログインポート時、以下の優先順位でリードを検索し、自動的に紐付けます。
            


            

              
              

                

                  
1

                  
メールアドレス一致

                  
最優先・一意性高

                

                

                  例: abc@example.com → LDI-00001 に紐付け
                

              


              
              

                

                  
2

                  
電話番号一致

                

                

                  例: +1-234-5678 → LDI-00002 に紐付け
                

              


              
              

                

                  
3

                  
顧客名 + 国 一致

                

                

                  例: ABC Trading + United States → LDI-00003 に紐付け（同名企業を国で区別）
                

              


              
              

                

                  
4

                  
顧客名のみ一致

                  
曖昧マッチ・警告

                

                

                  例: ABC Trading → 2件見つかった場合はスキップ（エラーレポートに記録）
                

              

            

          

        


        
        

          

            
            よくあるエラーと対処法
          


          

            

              

                

                  
                  DUPLICATE_EMAIL（メールアドレス重複）
                

                

                  原因: インポートしようとしたメールアドレスが既に登録済み
                

                

                  対処法: ① リード管理画面で既存データを確認 ② 「既存データを上書き」オプションを使用 ③ CSVから該当行を削除
                

              


              

                

                  
                  LEAD_NOT_FOUND（リード紐付け失敗）
                

                

                  原因: 会話ログの顧客情報が、どのリードにも一致しない
                

                

                  対処法: ① メールアドレスを正確に入力 ② 先にリード管理をインポート ③ 顧客名のスペルミスを修正
                

              


              

                

                  
                  MULTIPLE_MATCHES（複数リード一致）
                

                

                  原因: 同じ顧客名のリードが複数存在し、一意に特定できない
                

                

                  対処法: メールアドレスまたは国情報をCSVに追加して一意に特定
                

              


              

                

                  
                  INVALID_EMAIL（メール形式エラー）
                

                

                  原因: メールアドレスの形式が正しくない（@マークがない等）
                

                

                  対処法: user@example.com の形式に修正
